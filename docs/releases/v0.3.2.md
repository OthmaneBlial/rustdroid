# v0.3.2 — reliable failure receipts

Status: **source candidate, release not tagged or published**. Cargo metadata is 0.3.2; the currently published binary remains v0.3.1. Linux runtime and release gates below remain required.

## What is already on main
The previously published main baseline contains the changes listed below. Additional candidate changes supervise readers, start observation after readiness/PID discovery, check main-process continuity, and scope crash detection to a launch marker. Those changes have local tests but have not been verified on Linux/KVM. Source publication is separate from the release gates below.

- Failed runs after backend selection produce schema-v1 JSON, HTML, JUnit and Markdown receipts with a stable stage, classification and path-free summary.
- Best-effort artifact capture preserves the primary run failure when an additional log source is unavailable.
- HTML receipts escape ABI values correctly.
- SHA-256 receipt encoding is compatible with sha2 0.11; the known digest-vector test passes.
- Rust dependencies and workflow actions were updated. The Expo fixture uses Expo 57.0.20, React 19.2.3 and React Native 0.86.3; its workflow now checks SDK compatibility.

## Limits to retain in the published notes

Linux/KVM is the supported runtime. macOS CLI compilation is not macOS emulator support. A successful smoke receipt does not validate business flows or a device matrix. Failures before receipt ownership retain their documented stderr/exit-code limits. Logs can contain application data.

Replace this draft status and checklist with actual candidate/run/asset URLs only when those results exist. Do not move the existing v0.3.1 tag or relabel its binary.
