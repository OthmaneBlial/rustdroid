# Community and contribution flow

| Need | Where | What to include |
| --- | --- | --- |
| Setup question or workflow recipe | GitHub Discussions | Distro, backend, AVD/API, stable doctor IDs, redacted evidence |
| Reproducible defect | Bug issue form | Minimal command, expected/actual result, receipt/log excerpts |
| Environment failure | Setup issue form | `doctor --json`, KVM/SDK/AVD status, runner details |
| Feature proposal | Feature issue form | User problem, scope, non-goals, acceptance criteria |
| Security concern | Private vulnerability report | Follow [SECURITY.md](../SECURITY.md); never post publicly |

Labels identify contribution areas: `good first issue`, `help wanted`, `docs`, `ci`, `host-runtime`, `fixtures`, and `release`. Starter work must have scope, acceptance criteria, and a command that demonstrates success.

Questions belong in Discussions; Issues are for reproducible defects and accepted work. Response is best-effort, with a target acknowledgement within seven days, not 24/7 support.
